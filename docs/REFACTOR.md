# F13LD.sweep refactor (v0.20 → v0.27)

Session recap: [`SESSION_RECAP_2026-10-08.md`](SESSION_RECAP_2026-10-08.md) · what's next: [`NEXT_STEPS.md`](NEXT_STEPS.md).

Started 2026-10-07. Sweep is for quickly exploring a parameter space as a comparison; F13LD.lab is for full solves and verification. The refactor splits the single file into modules (like Lab and Mesh), fixes the v0.19.0 findings (`AUDIT_v0.19.0.md`) and moves the solver onto the GPU.

## Decisions (Matt, 2026-10-07)

- **Licence.** Solver files taken from F13LD.lab keep Lab's licence (PolyForm Noncommercial 1.0.0 + the reproduce/verify permission) inside this repo; everything else stays MIT.
- **Stretched cells.** The solver will handle non-cubic (stretched) cells, so cell scale becomes real physics for TPMS, noise and grain. Lab will incorporate it later.
- **Provenance.** Exports carry a solver version in their provenance; stiffness dropping once shear is solved is expected and fine.
- **Shear.** Report shear moduli (and the full stiffness) from the full 6×6 solve.
- **Beam.** Real voxel solve, like every other family, so all families are consistent.
- **Phases** approved in this order; Phase 1 approved to start.

## v0.24.0 — GPU solver (2026-10-08)
Matt's decisions this session: pull F13LD.lab's solver in (elastic and the now-live thermal); do steps A–C of the GPU plan in one branch; Sweep is for speed, so accuracy may be traded for it.

- **Lab's solver, unchanged.** `solver/lab/` = F13LD.lab v0.26.0 files byte-for-byte (`10-hardware`, `11-webgpu-device`, `12-fft-plan`, `12b-fft-cpu`, `14a-connectivity`, `16a`, `16b`, `16g`, `16i`, `17b`), PolyForm Noncommercial with Lab's NOTICE (`solver/LICENSE.md`, `solver/NOTICE`). `tests/parity/solversync.js` checks them. Sweep's additions: `solver/sweep-gpu-kernels.js` (stretched Γ̂ kernel, thermal stretch patch) and `solver/gpu-worker.js` (the GPU worker) — also PolyForm.
- **Pipeline split.** `54-estimate.js`: `prepareDesign` (geometry, gates, pores, curvature, topology, tortuosity) → solve → `finishDesign` (every derived metric). `estimateHomogenization` = the CPU path, numbers unchanged (harness). `55-estimate-gpu.js`: `prepareDesignGpu` (worker: + island trim, partial-volume voxels, cell edges) and `finishDesignGpu` (page: moduli from the 6 × 6). `60-solver-pool.js`: `GpuSolverClient`, `computeDesign` (CPU or worker → GPU → page).
- **Elastic:** Lab's fast path (16i `ElasticFastSolver`): full 6 × 6 from six load cases, GPU-resident CG, packed operator. Ex/Ey/Ez = 1/S diagonal; Gyz/Gxz/Gxy, ν, Zener ratio and the 6 × 6 reported. Disconnected axes report 0 as before; any modulus under 20 × void stiffness (≥ 1e-5 Es) counts as no load (Lab's sweep rule).
- **Thermal:** Lab's GPU conductivity solver (17b), three load cases at once, pore filler as before (k_void = 0.0003 k_solid). Solid fraction per voxel, wall normal 0 (Lab's isotropic blend).
- **Voxels as Lab:** partial volume on (4³ samples per surface voxel, `geom/voxels.js`), Lab's "networks" island trim (beams never trimmed). Sweep's VF / connectivity gates and metrics grids unchanged.
- **Stretched cells (step B).** Elastic: Willot's rotated frequency with per-axis spacing, ξ_α = sin(πk_α/N) Π cos(πk_β/N) / h_α, built on the GPU in 16i's packed layout (sin / cos tables in Float64). Cell edges: TPMS 1 / cell_scale, beam scale_xyz, noise / grain cubes.
- **Speed.** CPU workers prepare while the GPU solves; designs in flight on the GPU ("lanes", own solver buffers, shared FFT plan and cubic Γ̂): 6 at N ≤ 16, 4 at 32, 2 at 64. Fast: void 1e-3, CG tol 1e-3, thermal tol 1e-3. Rigorous = Lab's sweep settings: void 1e-6, tol 1e-4, thermal 1e-5. N = 64 offered with the GPU only.
- **Export (additive, Ingest shape unchanged):** per design `Gyz/Gxz/Gxy_GPa`, `G*_norm`, `nu_xy/xz/yz`, `zener_A`, `C_GPa` (6 × 6), `cell_aspect`, `island_trim_pct`, `thermal_converged`, `solve_ms`, `solver_version`; `meta.solver` gains `backend`, `gpu_adapter`, `void_ratio`, `gpu_cg_tol`, `gpu_cg_maxiter`, `thermal_cg_tol`, `partial_volume`, `island_trim`, `load_cases`. CPU-solved designs export exactly as v0.23.0.
- **UI:** Solver line (GPU + adapter, or CPU + reason); N = 64 button (GPU only); shear moduli as rank metrics and in the detail panel. `?gpu=0` forces the CPU solver.

## v0.26.0 — how designs are varied (2026-10-09)
Review and plan: [`FAMILIES_AND_JITTER_PLAN.md`](FAMILIES_AND_JITTER_PLAN.md). Matt's decisions: Neighbourhood is the default (a user can always load a new recipe — or seed — for disparate designs); density as a sampled axis fits the tool's intent; more seeds fundamentally change the space, so fresh seeds are an Explore option, not a Realisations setting; one shared Spread control; the inflated-stiffness flags and shear moduli go into Ingest / Vault in the families pass.
Numbers move on purpose: every design is drawn differently.
- **Density is drawn** (`41-density.js`). Sobol dimension 0 is a volume fraction drawn from the density window; the worker sets the design's thickness knob to hit it before building the geometry — TPMS solid offset / shell wall / PI pipe radius, noise and grain half-width (sheet, solid) or iso (half), beam strut radius (all axes and the node smoothing / ball together). The knob enters the margin field as ≈ a·k + c, so two evaluations at 4,096 low-discrepancy (R3) points give the fraction at any knob value; a pure threshold (offset, iso, half-width) is exact, others take one or two secant checks. The worker returns the solved recipe, which is what the table, exports and Mesh / Lab links carry. A target the knob can't reach within 2 points is discarded as `density_unreachable` (PI-TPMS tops out near 15–30 %).
- **Density window** in the Sweep column: Auto = the recipe's density ± Spread, inside the solver's range for the mode (RHO_MIN_* / RHO_MAX_*); typing a value switches to Set. A ρ rank pressure slides the density draw inside the window (as the axial pressures slide the scale draws). Gone: the v0.18 wall / half-width / pipe-radius multipliers, the beam radius-bound shift and the ρ pre-gate factors; beams no longer reuse the cell-scale % ranges for their radius.
- **Variation: Neighbourhood (default) / Explore.** Neighbourhood keeps the design's identity — TPMS terms, trig functions, frequencies, signs, per-term phases and the PI phase shift; the grain seed (same field, as Lab's adaptive sweep); noise seed, octaves and cellular metric; beam node treatment (none stays none) — and moves its continuous settings × (1 ± Spread) around the recipe's own values (TPMS coefficients and shell normal-weights, grain frequency / κ / wave counts / hyperuniform settings / direction, noise frequency and per-axis scale with the geometric mean held, beam radius proportions and node sizes). Explore is the v0.25 redraw plus fresh seeds (grain, noise), noise octaves ± 2 and metric, beam nodes drawn afresh.
- **Spread** (default 25 %, presets 10 / 25 / 50) — one control for every family; centre shifts (grain / noise sheet position) scale with it.
- **Sobol dimensions:** 0 density, 1–3 cell scale (TPMS, beam), then the family's settings in its own order (`ctx.u()`), then the seeded random stream. Grain and noise no longer waste the first dimensions.
- **Reference design #0:** the recipe itself, solved first with nothing changed, marked "ref" in the table; it rejoins the final list after the ranks (it is never ranked out) and is exported with `reference: true`. If it fails the gates (e.g. a recipe denser than the solver's range) the log says so and the sweep carries on.
- **Shear moduli gated** (GPU path): a shear modulus needs one connected piece spanning both axes of its plane (`computeSolidPercolation` → `shear_yz / xz / xy`); otherwise it reads 0 instead of the void's stiffness.
- Export: `meta.solver.variation`, `spread`, `density_window`; per design `target_vf`, `density_knob`, `density_knob_value`, `reference`. Shape otherwise unchanged.
- Settings remembered: variation and spread (not the density window, which follows the recipe).
- Checks: `node tests/density.js` (landing accuracy over the parity fixtures), `node tests/smoke-jitter.js` (jitter → density → CPU solve, no browser). Harness: numbers differ from v0.25.0 by design.
